# NTO Glados

## Обновление на хостинге

Используйте Python 3.10 или новее. В окружении, из которого запускается бот:

```sh
python -m pip install --upgrade -r requirements.txt
python -m pip check
python -m unittest discover -s tests -v
python main.py
```

После обновления файлов и установки зависимостей перезапустите сервис бота
через панель хостинга. Одновременно должен работать только один экземпляр.
Сохраните прежние переменные окружения, базу пользователей и файл счётчика.

### Если при запуске не найден moderation_content

`moderation_content.py` и `spam_patterns.py` — собственные модули проекта,
а `spam_rules.json` — файл правил. Их нужно загрузить вместе с `main.py`
и `chat_reader.py` в один каталог. Устанавливать их через pip не нужно.

Если хостинг разворачивает проект из Git, новые файлы должны быть добавлены
в коммит, отправлены в репозиторий, а затем включены в новое развёртывание.
Одного обновления уже отслеживаемых файлов недостаточно:

```sh
git add moderation_content.py spam_patterns.py spam_rules.json README.md tests
git status --short
```

После проверки списка изменений создайте коммит и отправьте его в ветку,
из которой хостинг разворачивает бота. Также включите изменённые `main.py`,
`chat_reader.py`, `database.py`, `requirements.txt` и оба файла шаблонов,
если они ещё не были отправлены. На сервере переустановите зависимости
командой выше и запустите новое развёртывание.

При ручной загрузке можно использовать `dist/bot-update.zip`: внутри файлы
лежат сразу в корне, без дополнительной папки. Распакуйте их в каталог
с серверным `main.py`. Архив не содержит `.env`, `users.db`,
`counter_state.txt`, журналов или локального Python-окружения; сохраните
существующие данные и настройки хостинга.

В `requirements.txt` закреплён aiogram 3.31.0 с поддержкой
`rich_message` и `expandable_blockquote`. Более старая версия из лога
не могла разобрать ответ `getUpdates`, поэтому обработка всей очереди
останавливалась ещё до вызова обработчиков.

Составной пост пересылается методом `forwardMessage` по ID исходного сообщения:
его текст, фото и видео не нужно вручную собирать заново.
Сбрасывать очередь обновлений (`drop_pending_updates`) для этого исправления не нужно.
Тесты выполняются локально с имитацией Telegram API и ничего не отправляют в чат.

## Модерация

Фильтры проверяют обычный текст, подписи, выбранный текст цитаты и вложенные
блоки `rich_message`, включая скрытые ссылки и кнопки. Полное сообщение,
на которое участник просто отвечает внутри чата, не считается текстом его сообщения.

Для новичков пересылки и внешние ответы разрешены только из текущего чата
и исходного канала олимпиады (`SOURCE_CHANNEL`). Если источник неизвестен
или скрыт, сообщение удаляется с предупреждением. Доверенный источник
не отменяет остальные проверки ссылок, медиа и спам-паттернов.

Редактирования повторно проходят проверки содержимого. Они не увеличивают
число сообщений для получения статуса проверенного и не учитываются как флуд.
Условие получения статуса и послабления для проверенных участников прежние:
три сообщения, прошедшие фильтр новичков. Время участия не учитывается.

За сообщения только из эмодзи новичок получает удаление и предупреждение;
третье предупреждение приводит к бану, как и для остальных предупреждений.
Явные жёсткие спам-паттерны по-прежнему приводят к немедленному бану новичка.

Предупреждения хранятся в новой таблице `moderation_warnings` в существующей
базе `users.db`. Таблица создаётся автоматически при запуске, данные участников
сохраняются. Повторная обработка одного сообщения не добавляет ещё одно
предупреждение. После успешного бана предупреждения очищаются; при ошибке
бана сохраняются для следующей попытки. Предупреждения из памяти старой версии
восстановить после её остановки невозможно.

Для сохранения предупреждений между перезапусками и развёртываниями база
должна находиться на постоянном диске хостинга. Новых переменных окружения
для этих изменений не требуется.

## Шаблоны антиспама

`patterns_hard.txt` содержит самостоятельные запреты чата: `$`, `₽`, `18+`,
интим, порно, казино и букмекерскую рекламу. Для новичка совпадение означает
немедленный бан. Те же запреты в `patterns_soft.txt` удаляют сообщение
проверенного участника без немедленного бана.

Каждая непустая строка — фраза. Строки, начинающиеся с `#`, — комментарии.
Повторы игнорируются. Совпадения проверяются по границам слов: `class`
не совпадает с `myclass`. Звёздочка в конце слова разрешает окончания:
`подработ*` совпадает с «подработка», «подработку», «подработки».
Одиночные неоднозначные слова, национальности, языки и флаги не служат
основанием для наказания. Возрастная отметка `16+` больше не является триггером.

В `spam_rules.json` описаны девять сочетаний рекламных признаков:
работа с оплатой и приглашением в личку; лёгкий заработок с быстрыми выплатами;
оплата аренды аккаунтов или оформления карт; платные отзывы и выкупы с приглашением
в личку; обещания гарантированного инвестиционного дохода; раздачи с перенаправлением;
реклама ставок; реклама VPN; услуги накрутки. Внутри `all` должны совпасть
все группы, а внутри каждой группы достаточно одной фразы.
Отдельное слово «оплата», «подработка», «крипта» или «VPN» не срабатывает.

Совпадение составного правила удаляет сообщение: новичку также выдаётся
сохраняемое предупреждение, с баном на третьем предупреждении. Для проверенного
участника остаётся удаление без предупреждения. Название сработавшего правила
записывается в лог. Это эвристики: обсуждение рекламы с теми же формулировками
может дать совпадение, поэтому рекламные сочетания не вызывают немедленный бан.

Перед сравнением нормализуются регистр, совместимые Unicode-символы, `ё`/`е`,
некоторые похожие буквы разных алфавитов, невидимые символы, повторы букв и
подмены `0`/`6` внутри слов. Известные ключевые слова распознаются и при
написании с пробелами между буквами. Исходные сообщения не изменяются.
Нормализация не гарантирует обнаружение любых способов маскировки.

При обновлении загрузите вместе с остальным проектом `spam_patterns.py`,
`spam_rules.json` и оба файла `patterns_*.txt`. После изменения правил
перезапустите бота. Отсутствие `spam_rules.json` отмечается в логе предупреждением;
тогда работают только остальные фильтры. Проверка формата правил выполняется
при запуске.
